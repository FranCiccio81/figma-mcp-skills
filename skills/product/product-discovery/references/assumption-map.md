# Assumption map

Rank each assumption on two axes, then test the top-right quadrant first.

| | Weak evidence | Strong evidence |
|---|---|---|
| **High importance** (the idea fails if wrong) | Test first | Monitor |
| **Low importance** | Park | Ignore |

## Risk types

| Risk | Question | Typical cheap test |
|---|---|---|
| Desirability | Do people want this, and is the problem real and frequent? | Problem interviews on past behaviour, landing page or fake door with a pre-set threshold |
| Usability | Can people understand and use it? | Paper or clickable prototype, five-user usability test per segment |
| Feasibility | Can we build and run it with our stack, data and team? | Spike, technical prototype, vendor check |
| Viability | Does it work for the business, legal and compliance? | Unit economics sketch, legal review, pricing test |

## Writing a testable assumption

`We believe that <segment> <behaviour or belief>. We will know this is true when <observable signal>
reaches <threshold> in <test> by <date>.`

The threshold is fixed before the test. A result below threshold is a finding, not a failure to explain away.
